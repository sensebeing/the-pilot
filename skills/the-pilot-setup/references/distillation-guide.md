# Distilling scenes and shortcuts from recent chat history

Run `pilot distill --days 7 --json` (optional `--max-sessions 80`). The command performs a read-only scan of the user's recent conversations across Antigravity/Gemini CLI, Claude Code, Codex, and Cursor, filters out machine-generated Orca worker or architecture reviewer preambles, separates already-active Autopilot expansions, and clusters recurring manual user prompts. It is evidence, not an automatic configuration write.

## What the report contains

- `sources`: per-agent counts of discovered session files, sampled session files, extracted human messages, and filtered machine preambles over the 7-day window.
- `autopilot_activity`: counts of prompts already generated by installed scenes, candidate switches (`,1`, `,2`), or shortcuts.
- `recurring_patterns`: normalized manual prompt signatures (`<id>`, `<url>`, `<path>`, `<n>`) that appeared at least twice, with `turn_role` (`entry`, `followup`, or `mixed`), agent list, workflow `category`, representative `examples`, and `suggested_automation`.
- `sampled_prompts`: recent manual `entry` and `followup` prompts across agents so you can spot semantic repetitions even when wording varies.
- `recommendations`: prioritized configuration suggestions derived from the observed patterns.

## How to turn patterns into configuration

1. **Repeated manual continuation nudges (`continue_nudge`)**:
   When the user repeatedly types `"继续"`, `"continue"`, or `"proceed"`, recommend `autopilot.mode = "gate"` (or raising `max_consecutive_auto_turns`) so routine `Class A` turns advance automatically while `Class B` decisions still pause.
2. **Repeated review, verification, or closeout prompts (`architecture_review`, `deliver_and_verify`, `closeout_and_sync`)**:
   - Map recurring review instructions to `architecture-re-review` and fold specific quality criteria into `scenes.guardrails`.
   - Map recurring merge, deploy, or verification instructions to `scenes.deliver_strategy` (`merge_dev_only`, `merge_dev_e2e`, or `local_verify_only`). If the user frequently runs a custom verification or release check mid-session, propose a `shortcuts.custom_comma` alias.
   - Map recurring documentation, ledger, or worktree cleanup prompts to `closeout-and-sync` (or `.pilot/project.json` `scene_specs.closeout-and-sync.fallback_prompt` for team-wide rules).
3. **Repeated session openers (`entry` role / `plan_and_dispatch` / `entry_workflow`)**:
   When a session opener repeats with different IDs, paths, or URLs (`<id>`, `<path>`, `<url>`), extract a parameterized `{arg}` template and propose a short `shortcuts.custom_entry` command (or add it to `.pilot/project.json` if shared with teammates).
4. **Semantic review of `sampled_prompts`**:
   Read `sampled_prompts` to identify multi-turn habits that differ in surface phrasing but share the same intent, and include them in your recommendation summary.

Always present the distilled evidence (pattern, frequency, and proposed scene, guardrail, or shortcut) and confirm with the user before running `pilot apply`. For tests and isolated demonstrations, always pass explicit temporary `--home-dir` and `--gemini-dir` paths.
